## 结论

项目有可运行的前端和后端，适合这次活动的规模。已修复确认的问题并验证本地完整流程；目前没有购买服务器和域名，因此**尚未上线公网**。买好资源后仍需在实际 Ubuntu 云主机完成安装、HTTPS 和校园网/微信验收。

不需要为这次活动额外购买数据库。推荐单台 2 核 2GB、Ubuntu 24.04、有公网 IP 的轻量服务器；应优先询问学校现有资源。大陆与香港节点的选择、购买步骤、上传命令和二维码流程见 [部署教程](deployment.md)。

## 已修复的问题

| 问题 | 修复后的行为 |
|---|---|
| 原退出流程先禁止文件轮转，最后保存也被禁止；400ms 延迟保存还会先向用户报成功 | 每次提交、审核、删除先同步保存并原子替换主文件，再返回成功；退出没有未保存队列 |
| 保存失败只记录日志，前端仍可能显示成功 | 返回 503 并恢复内存状态，用户表单保留 |
| 请求体逐个 Buffer 转成字符串，中文/emoji 跨包可能损坏 | 收集字节后统一 UTF-8 解码 |
| JSON `null` 请求可能没有响应，部分非对象/字段类型产生错误行为 | 请求必须是 JSON 对象，字段必须为文本；格式问题返回 400 |
| 去重忽略作者和 QQ；删除后再投递可能被旧去重记录吞掉；重启失去短期去重 | 去重覆盖全部表单字段，删除清理键，重启恢复近期记录，重复提交返回原 id |
| 管理员退出只清浏览器，服务器 token 仍有效 | 后端撤销会话；生产拒绝默认和过短密码；登录限流独立于学生投递 |
| 数据损坏后以空库运行，可能覆盖历史记录 | 尝试备用文件；全库不可用时写恢复标记并停止，自动重启仍停止，恢复有效主数据后解除标记 |
| 连续出现超过三条提示时，异步移除与 while 循环导致页面卡死 | 同步限制提示数量，最多保留三条 |
| 换信或切页后，旧动画仍读取新的/空的信件 | 动画带序号和页面检查，换信/切页取消旧结果 |
| 学生和管理员停留页面期间，看不到新审核/新投递 | 可见页面每 30 秒同步，另有手动刷新入口 |
| 图书角只显示前五行，后台全文靠鼠标悬停，手机不能完整阅读/审核 | 图书角可展开全文；后台用可展开的详情；同步更新保留展开状态 |
| 剪贴板失败也提示复制成功，导出无统一超时处理 | 复制根据实际结果提示；导出复用统一 API 超时与鉴权处理 |
| 本地演示和真正共享站点容易混淆 | 双击 HTML 明确提示本地数据不共享 |
| 已有 `/usr/bin/node` 时，部署服务仍固定从 `/usr/local/bin/node` 启动 | 使用实际 Node 路径；需要安装时下载 Node 24 并校验 SHA256 |
| 部署提前开放后台端口，HTTPS 脚本未处理已启用的系统防火墙 | 默认后端只监听回环；公开入口 80/443；处理已启用的 UFW 规则 |
| HTTPS 脚本忽略已有配置的真实端口，域名未充分校验 | 读取服务端口、校验域名参数，域名/端口不匹配时要求检查已有 nginx 配置 |
| Ubuntu cron 对 CRON_TZ 支持不确定，备份缺少校验 | 使用带 Asia/Shanghai 时区的 systemd 定时器，校验 JSON 后原子写备份，保留约 14 天 |
| 自检对 HTTPS 目标发送明文 TCP；压测可能忽略连接错误或大样本报错 | 自检用 TLS，压测正确统计并将连接错误判为失败，修正抽样和延迟统计 |
| 旧教程把微信不拦截、节点延迟和每条内容流量写成固定保证 | 重写为条件说明与真机验收要求，不承诺微信一定放行，不引用未经复测的旧性能数据 |

## 验证结果

初次检查执行 `npm test`：**15 项测试全部通过**。其中包括完整投递与审核流程、30 次并发重复提交、UTF-8 中文分包、超大请求、跨站写入、模拟磁盘写入失败、退出后 token 撤销、重启持久化、备份恢复，以及全库损坏后连续两次启动拒绝空库。本轮新增覆盖见上方复核记录。

自动测试使用系统临时目录，未修改项目原 `data/notes.json`。真实活动数据、备份与本机路径不纳入源码仓库。

接口自检：**22 项全部通过**，验证页面、压缩、公开内容过滤、鉴权、畸形 URL 请求和接口响应。

最后一轮本机 Node 24.16.0 测试使用 **300 条已审核、每条 2000 字的心得**：

| 场景 | 结果 |
|---|---|
| 300 个虚拟用户同时读取首页和三个 API | 1200 次请求，全部 HTTP 200；无连接错误、5xx 或超过 8 秒的请求 |
| 图书角 API 读取延迟 | p95 约 50ms，p99 约 50ms |
| 50 个虚拟用户各浏览后同时提交 | 250 次请求，200 次 HTTP 200、50 次 HTTP 201；50 条都保存成功 |
| 50 并发提交延迟 | p95 约 629ms，p99 约 654ms |

这些是本机回环测试结果，不代表香港/大陆云主机的网络延迟，也不是整个网站加载完成时间。云主机磁盘、带宽、学生网络和字体下载都会影响实际体验。

## 上线前还需完成

1. 购买或申请服务器、域名；确定学校允许的托管与审核方式。
2. 按教程实际运行 Ubuntu 安装和 HTTPS 脚本；证书签发和续期未在本机 Windows 上执行。
3. 让两位同学分别用校园网、手机流量，通过微信最终二维码完成提交与公开验证。桌面 Chrome 模拟手机尺寸不能替代微信真机。
4. 定期在后台审核与导出数据。同机备份不能防整台服务器丢失，应另存电脑或异地。

保留原审核逻辑：提交先待审核，通过后才出现在公开页和拆信池。网站提供文本心得、昵称、书名、作者和选填 QQ，不包含账号注册、微信登录、图片/附件上传功能。

当前快照存储按单进程设计。不要启动多个 Node worker 共同写文件；未来若变成长期、大量投稿的站点，再迁移数据库与分页。
