# 一纸书缘：购买服务器、上线和日常管理

这个项目有前端和 Node.js 后端，不是只有静态页面。正式上线后的路径是：同学通过链接或二维码访问 HTTPS 域名 → nginx 转发给 Node → 心得保存在服务器的 `data/notes.json` → 管理员审核通过 → 所有访客可以在图书角和拆信页看到。

约 300 人在几天或几周内分批访问，一台小型服务器就可以，不需要购买数据库、负载均衡或 Kubernetes。你关闭自己的电脑后，云服务器仍会继续运行。服务器和域名必须保持有效期，活动期间不要停机。

**当前还未部署到公网**：你还没有服务器和域名。本地测试通过不等于公网、校园网或微信真机已经通过。下面依次完成购买、上传、HTTPS 和真机验收。

## 1. 先选部署地点

优先向学校/图书馆问：“是否有对公网开放的服务器、可用于活动的子域名，以及网站审核流程？”有现成资源时通常不用自行购买，也容易长期维护。

| 方案 | 适用情况 | 购买前确认 |
|---|---|---|
| 学校现有服务器和域名 | 学校允许托管活动网站 | 公网访问、域名、HTTPS、上传代码权限和内容管理负责人 |
| 大陆云服务器 | 重视校园内访问稳定性，可以等待手续 | 使用域名前按服务商要求完成 ICP 备案；UGC 活动网站应如实说明用途，个人/学校主体如何办理先咨询服务商与学校 |
| 香港云服务器 | 活动较急，需要较快部署 | 一般不走大陆服务器的 ICP 接入备案流程，但仍须遵守适用法律和平台要求；校园网到该节点的访问速度要实测 |

**香港节点不能保证微信不拦截，大陆备案也不能保证微信永不拦截。** 正常域名、有效 HTTPS 和清楚的活动信息有助于正常访问，最终以微信扫码真机测试为准。不要依据“某个地区一定免风控”的宣传选购。

## 2. 购买什么、怎么购买

可以在 [阿里云](https://www.aliyun.com/) 或 [腾讯云](https://cloud.tencent.com/) 选“轻量应用服务器”。也可以选学校认可的其他服务商，代码不绑定某家公司。

建议配置：

| 项目 | 选择 |
|---|---|
| CPU / 内存 | **2 核 / 2GB**，这个规模留有余量 |
| 系统 | **Ubuntu 24.04 LTS**（22.04 也支持） |
| 硬盘 | 40GB 或以上，持久磁盘 |
| 网络 | 有独立公网 IPv4；3–5Mbps 或更高，确认月流量包和超额计费 |
| 镜像类型 | 纯操作系统；不需要宝塔、WordPress 或预装数据库 |
| 期限 | 覆盖准备期、整个活动期和至少一段数据整理时间 |
| 域名 | 一枚你拥有的域名，或学校分配的子域名 |
| HTTPS 证书 | 本项目用 Let's Encrypt 免费证书，通常不用另买付费证书 |

购买顺序：

1. 注册并完成云账户所需认证；学生优惠是否适用以控制台为准。
2. 选择部署地区，再选 2 核 2GB、Ubuntu 24.04。核对公网 IP、带宽/流量、到期时间、续费价格和退款规则。价格会变，以订单页为准。
3. 创建服务器，记下公网 IPv4 和登录用户（控制台通常会明确说明是 `ubuntu` 还是 `root`）。优先用 SSH 密钥；使用密码时不要把密码发进聊天或截图。
4. 注册域名，完成注册商要求的实名流程。域名可在任何支持 DNS 管理的注册商购买，无须与服务器同一家。
5. 选择大陆服务器时先咨询备案接入流程，完成必要手续后再对外发布正式网站。

不需要因为“总人数 300”购买昂贵的高并发套餐。带宽质量、持续运行、备份和域名可访问性更重要。这里只给配置建议，没有替你下单，也没有查询实时优惠价格。

## 3. 云防火墙与域名解析

在轻量服务器“防火墙”（ECS 是“安全组”的入方向）配置：

| TCP 端口 | 来源 | 用途 |
|---|---|---|
| 22 | 尽可能仅管理员自己的公网 IP | SSH 上传和登录；公网 IP 变化时更新规则 |
| 80 | `0.0.0.0/0` | HTTP 跳转、免费证书签发和续期 |
| 443 | `0.0.0.0/0` | 正式 HTTPS 网站 |

**不用开放 8080**。Node 只监听服务器的 `127.0.0.1:8080`，公网统一通过 nginx 的 443 端口访问。云防火墙和服务器内的 UFW 是两层；HTTPS 脚本在 UFW 已启用时放行 80/443，不会擅自启用 UFW 或更改 SSH 规则。

在域名 DNS 控制台新增一条记录：

| 类型 | 主机记录 | 记录值 |
|---|---|---|
| A | `shuyu`（使用 `shuyu.你的域名`）或 `@`（根域名） | 服务器公网 IPv4 |

没有可用公网 IPv6 时，不要添加 AAAA 记录。仅软件监听 IPv6 并不能让服务器自动拥有公网 IPv6。

建议第一次上线先不用 CDN、代理 DNS 或额外 WAF，按本说明直接解析到服务器。启用其他代理后需要重新配置可信代理链。

## 4. 从 Windows 上传代码

在 Windows PowerShell 中打开项目目录。下面的 `ubuntu`、`公网IP` 必须换成你的真实信息；控制台若说明登录用户是 `root`，就把 `ubuntu` 改成 `root`。

```powershell
cd C:\你的项目目录\yizishuyu
ssh ubuntu@公网IP "mkdir -p /tmp/yizishuyu-upload"
scp .\server.js .\index.html .\package.json .\backup.js .\smoke-test.js .\loadtest.js .\integration-test.js .\frontend-test.js .\setup.sh .\setup-https.sh ubuntu@公网IP:/tmp/yizishuyu-upload/
ssh ubuntu@公网IP
```

首次 SSH 会提示服务器指纹，核对控制台提供的信息后接受。SSH 输入密码时屏幕不显示字符是正常现象。如果 Windows 提示没有 `ssh` 或 `scp`，到“设置 → 可选功能”安装 OpenSSH 客户端，也可以用云控制台的远程终端与文件上传功能。

上传的是程序，不会把本地测试数据发布出去。如果将来需要迁移真实数据，先备份再单独操作，不要随意覆盖线上 `data` 目录。

## 5. 在服务器安装

下面开始是在 SSH 登录后的 **Linux 终端** 执行：

```bash
sudo bash /tmp/yizishuyu-upload/setup.sh
```

脚本会安装运行环境（已有受支持 Node 时复用其真实路径）、创建独立服务用户、生成随机管理员密码、配置开机自启和故障重启，设置北京时间每天 03:00 的自动备份，并执行本机健康检查。程序位于 `/opt/yizishuyu`，密码配置位于 `/etc/yizishuyu.env`。

如果输出失败，不要继续跳过；查看提示与服务日志：

```bash
sudo systemctl status yizishuyu --no-pager
sudo journalctl -u yizishuyu -n 50 --no-pager
curl -f http://127.0.0.1:8080/api/health
```

首次安装在公网打不开 8080 是正常的，下一步配置 HTTPS 后才提供公网入口。这里脚本针对全新、专用于该活动的 Ubuntu 主机；已有其他网站的主机需先核对 nginx 配置，避免站点冲突。

## 6. 开通 HTTPS

DNS A 记录生效、云防火墙 80/443 放行后，在服务器执行（替换域名和邮箱）：

```bash
sudo bash /opt/yizishuyu/setup-https.sh shuyu.你的域名.com 你的邮箱@example.com
sudo certbot renew --dry-run
```

脚本会安装 nginx、配置反向代理、申请证书、把 HTTP 重定向到 HTTPS 并启用证书续期。如果 DNS、80 端口或证书签发失败，先处理错误再重新运行。不要短时间反复申请新证书。

此时正式网站为 **`https://shuyu.你的域名.com/`**，任何人都用同一个链接。更改域名或后端端口时，现有 nginx 配置会要求人工检查，防止覆盖证书设置。

管理员密码查看方式：

```bash
sudo cat /etc/yizishuyu.env
```

私下保存 `ADMIN_PASSWORD=` 后面的内容。点击网站“后台”登录。默认的 `admin888` 仅用于本地演示，生产环境会拒绝默认或不足 16 位的密码。

## 7. 二维码与上线验收

二维码只编码正式的完整 HTTPS 链接，可以使用 [草料二维码](https://cli.im/) 的网址二维码功能。网站用于普通微信网页访问，不是小程序；这个版本不需要申请小程序或接入微信登录。

**先验收再印海报**：

- 在电脑和手机流量下打开正式 HTTPS 链接，确认没有证书警告。
- 在校园网下打开一次，再用微信“扫一扫”扫最终下载的二维码；Android 和 iPhone 有条件时各测一次。
- 同学 A 投递一条真实测试心得；管理员在后台刷新后能看到完整内容。
- 未审核时，同学 B 不能看到这条心得；后台点击“入图书角”后，同学 B 刷新图书角可以看到并可以拆到。
- 后台拒绝/重置/删除后刷新公开页，对应心得应消失。
- 导出 JSON 到电脑，确认可打开且中文完整。QQ 号选填；填入后会随公开拆信内容提供给访客。
- 服务器重启后心得仍在：`sudo systemctl restart yizishuyu`，再次核对。
- 只读自检：`cd /opt/yizishuyu && node smoke-test.js https://shuyu.你的域名.com`。
- `sudo systemctl list-timers --all` 能看到备份和证书续期定时器。

访客图书角、拆信池和已登录后台在页面可见时每 30 秒同步；也可以用刷新按钮立刻读取。没有管理员持续审核，提交不会自动公开，这是现有网站的审核流程。

如果微信提示风险，核对域名、证书和页面内容，再通过提示页提供的渠道申诉。有效 HTTPS 不能绕过微信判断。海报可补充“如微信无法访问，请复制链接到浏览器打开”，但若微信连链接都不允许打开，该兜底仍需同学手动输入域名。

## 8. 活动期间维护与备份

```bash
sudo systemctl status yizishuyu --no-pager        # 运行状态
sudo journalctl -u yizishuyu -n 50 --no-pager      # 最近日志
sudo systemctl restart yizishuyu                 # 重启
sudo systemctl start yizishuyu-backup.service    # 立即生成备份
sudo journalctl -u yizishuyu-backup.service -n 20 --no-pager
df -h                                           # 检查磁盘空间
```

| 文件 | 用途 |
|---|---|
| `/opt/yizishuyu/data/notes.json` | 当前活动数据 |
| `/opt/yizishuyu/data/notes.json.prev` | 上一次成功变更前的数据 |
| `/opt/yizishuyu/data/backups/notes-YYYY-MM-DD.json` | 每日备份，保留约 14 天 |
| `notes.json.corrupt-*` | 无法解析的原文件，保留用于排查 |
| `recovery-required` | 全库不可用标记，防止自动重启误建空库；恢复有效数据后自动移除 |

每次提交、审核或删除都会先保存临时文件并同步磁盘，再原子替换主文件，成功后才响应。保存失败返回错误并恢复内存。启动时依次尝试主文件、上一版、临时文件；已有文件全部损坏时停止启动，要求恢复备份，不会假装空库正常运行。

每天备份在同一台服务器上，只能防部分误操作，**不能防整台服务器/磁盘丢失**。活动期间定期从后台导出到自己的电脑，或安排异地备份。旧导出文件不包含导出之后的新提交；删除公开内容前确认备份日期。

从指定日期恢复（先挑实际存在的备份文件）：

```bash
sudo systemctl stop yizishuyu
sudo cp /opt/yizishuyu/data/notes.json /opt/yizishuyu/data/notes.json.before-restore
sudo cp /opt/yizishuyu/data/backups/notes-2026-10-11.json /opt/yizishuyu/data/notes.json
sudo chown yizishuyu:yizishuyu /opt/yizishuyu/data/notes.json
sudo systemctl start yizishuyu
```

如果主文件已不存在，跳过保留 `before-restore` 那一步。恢复会回滚该日期之后的更改，务必先确认备份内容。

更新程序时重新上传并运行 `setup.sh`，它保留数据与已有密码。服务重启后管理员需重新登录。活动结束先导出并核对，再考虑停服务、取消续费；不要先销毁服务器再找数据。

## 9. 本地维护与测试

```powershell
npm start
# 浏览器访问 http://127.0.0.1:8080
# 另开终端：
npm test
```

`npm test` 自动启动临时实例，验证提交、审核公开、并发去重、中文分包、持久化、写入失败、备份恢复、鉴权与 300 并发读取，不触碰项目原数据。正式上线后应在云主机上复核，但不要对生产实例使用带 `--submit` 的压测。

直接双击 `index.html` 是 **本地演示**，数据只在当前浏览器，不能给同学共享。不要用静态页面托管代替本项目的 Node 后端，也不要用会随容器重建消失的临时磁盘存正式数据。

环境变量：

| 变量 | 默认/安装值 | 说明 |
|---|---|---|
| `ADMIN_PASSWORD` | 安装时随机生成 | 生产至少 16 位，建议随机 32 位 |
| `PORT` | 8080 | 后端端口；变更时 nginx 也要改 |
| `BIND_HOST` | `127.0.0.1` | 通过 nginx 提供公网入口 |
| `TRUST_PROXY` | HTTPS 安装后为 1 | 仅信任直接相连的 nginx，后端不能暴露公网 |
| `RATE_LIMIT_PER_HOUR` | 0 | 不按校园出口 IP 限制学生投递 |
| `MAX_NOTES` | 5000 | 总记录容量；普通活动远低于它 |
| `DATA_DIR` | 程序目录内 `data` | 测试可改为临时目录；生产变更还要调整 systemd 写权限 |
| `LOG_ACCESS` | 0 | 设为 1 可诊断请求，平时关闭 |

这是**单 Node 进程、单台服务器**的数据存储。不要用 PM2 cluster 或启动多个进程共同写同一个文件。约 300 条心得足够；如果未来扩展到长期运营、大量投稿或多服务器，应迁移到数据库并做公开分页。全量公开响应的大小取决于心得长度，不能用固定“每条几十字节”估算手机流量。

可在 [检查报告](check-report.md) 查看此次修复和验证范围。部署脚本目前完成语法检查，实际 Ubuntu 安装、证书签发、公网连通与微信扫码需要买好资源后完成。
